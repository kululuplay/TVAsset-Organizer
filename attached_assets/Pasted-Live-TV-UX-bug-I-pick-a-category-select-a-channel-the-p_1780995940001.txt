Live TV UX bug: I pick a category, select a channel, the preview window opens and plays fine. But when I go fullscreen, the stream does NOT continue seamlessly — the channel RESTARTS from scratch in fullscreen (re-buffering, black screen, reconnect). Professional IPTV apps (e.g. TiViMate) transition the SAME running stream from preview to fullscreen with zero interruption. Fix it that way:

Use ONE player instance and ONE running stream for both preview and fullscreen. Do NOT stop the preview player and start a new fullscreen player. The transition must reuse the exact same MediaPlayer/ExoPlayer that is already playing, with no stop/release/re-prepare and no new network connection.
Transition the VIEW, not the playback. Going fullscreen should only change the size/layout of the existing video surface (animate/expand the preview SurfaceView to fill the screen, or move the same player into a fullscreen container), while playback keeps running uninterrupted.
Avoid surface re-creation. A SurfaceView destroys and recreates its surface when it's removed/re-added or resized in certain ways — on this Amlogic hardware that causes exactly the restart/green behavior we already fought. Keep the same surface alive across the transition: prefer resizing/reparenting the existing SurfaceView without detaching the player from it, rather than creating a new SurfaceView in a new activity/fragment. If a fullscreen Activity is unavoidable, share the surface or hand off the player without re-prepare.
Single-connection safety: because the stream is reused, there must NEVER be a moment where a preview connection and a fullscreen connection are both open — that would trigger the "account in use on another device" error. One stream, continuously, throughout the transition.
Reverse transition too: exiting fullscreen back to preview must also keep the same stream running without restart.

Verify on the real stick: select a channel → preview plays → go fullscreen → the SAME video continues instantly with no black screen, no re-buffering, no reconnect; exit fullscreen → still continuous. Confirm only one server connection is active throughout.
