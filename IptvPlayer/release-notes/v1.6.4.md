Stablere Wiedergabe auf TV-Sticks und Android-TV-Geräten: verhindert endlose Neustart-Schleifen bei leichten Bildrucklern, behebt dauerhaft blockierte Senderstarts ohne Neustart des Sticks und korrigiert „Parsing-Fehler“ bei App-Updates.

Details for maintainers (not published in the update prompt):

- Anti-stutter loop (`ConsecutiveFailureRecoveryPolicy`, `ExoPlayerEngine`, `PlayerController`): quality-only stutter verdicts (`FRAME_DROP_RATIO` and `DECODER_HICCUPS`) now fire only when an untried alternative video stage exists (`hasAlternativeStageForCurrentFormat`). When no alternative stage exists (e.g. an Amlogic stick where `VLC_HW` is bypassed and `VLC_SW` is withheld for HD, or after both `EXO` and `VLC_HW` have been tried), the controller keeps the active stream playing instead of falling through to `engageReconnect()` and tearing down the stream every few seconds.
- Interlaced fail-fast route resolution (`ExoPlayerEngine`, `PlayerController`): `videoFallbackAvailable` now passes `currentVideoInterlaced` before `lastVideoVerdict` is populated so `InterlacedExoPolicy.failFast` accurately detects the Amlogic interlaced software rescue in `AUTO` mode.
- Default `BufferMode.ADAPTIVE` (`Models.kt`, `PlayerController`, `ExoPlayerEngine`, `VodPlayerActivity`, `SettingsActivity`): `BufferMode.fromName(null)` now defaults to `ADAPTIVE` (starts with `NORMAL`'s 1.5 s / 2.5 s thresholds and escalates to `HIGH`'s 5 s reserve after repeated rebuffers, while honouring `PlaybackRouteMemory.seedRebuffers` and remote `deviceOverrides.bufferMode`).
- Strict 1-connection socket safety (`ExoPlayerEngine`, `PlaybackRemotePolicy`, `telemetry-store.js`): `ExoProviderConnection` now uses a cached thread pool so one blocked `HttpURLConnection.close()` cannot stall subsequent socket closures. `releaseAndThen` and `play(reset = true)` wait a bounded time (`1500 ms` / `600 ms`) for the previous socket to close by default so strict 1-connection IPTV panels do not see overlapping connections; operators can opt into asynchronous socket close via `asyncZapSocketClose` in `playbackPolicy` or `deviceOverrides`.
- Self-healing stick recovery without power cycle (`TvPlaybackSession`, `HomeActivity`, `PlayerActivity`, `VodPlayerActivity`, `PlaybackProcessRecovery`, `ConsecutiveFailureRecoveryPolicy`): OS audio-focus refusal on TV sticks (stuck voice assistant or HDMI-CEC focus) no longer blocks channel/VOD startup. `PlaybackProcessRecovery` falls back to `-1L` when `/proc/<pid>/stat` is unreadable (relying on the kernel Binder token). Three consecutive non-authoritative terminal channel failures without any stable playback automatically trigger a controlled `:playback_recovery` process recycle; `HomeActivity` implements `PlaybackProcessRecoveryTargetProvider`.
- APK update "Parsing-Fehler" fix (`ApkInstaller`, `AboutActivity`, `file_paths.xml`): downloaded APKs are `fsync`ed and marked world-readable; Android 6.0 (API 23) stages a `file://` URI (since API 23 `PackageInstallerActivity` rejects `content://` URIs with `DLG_PACKAGE_ERROR` / "Parsing-Fehler"; only that path gives parent directories the traverse bit, never the read bit), and API 24+ grants read URI permissions across all resolved and known system/OEM installer packages.
- Low-RAM UI & Android 14+ background sync hardening (`LowEndUiBudget`, `IptvApp`, `PlaybackAwareSync`, `SyncWorker`, `DeferredSyncWorker`): constrained sticks enable `RGB_565` in Coil (`allowRgb565 = true`); background sync catches `Throwable` (including `OutOfMemoryError`) and caps WorkManager retries (`MAX_RUN_ATTEMPTS = 4`).

Android 6.0 or newer (API 23). Production package: `com.iptv.player`; version code: `150`.
