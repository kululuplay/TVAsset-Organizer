Flüssigere Wiedergabe auf Fire TV Sticks und Android-TV-Geräten: weniger Ruckler und unnötige Neustarts beim Senderstart und bei kurzen Netzschwankungen.

Details for maintainers (not published in the update prompt):

- MPEG-TS extraction (`LiveTsExtractorPolicy`): `FLAG_ALLOW_NON_IDR_KEYFRAMES` + `FLAG_DETECT_ACCESS_UNITS` on the live `TsExtractor` (same MODE_SINGLE_PMT and DVB subtitle transcoding as before), timestamp search window 1500 packets. Re-muxed provider streams without AUDs or with recovery-point keyframes no longer wait for an IDR or emit late/merged access units.
- PixelCopy (`SurfaceValidationPolicy`): no GPU readback at all where the pixel verdict is advisory (Fire TV default, or no alternative video stage) or on the Home preview thumbnail; native frame cadence or the validation deadline decide, exactly as when PixelCopy was unavailable. Where the verdict is authoritative the readback validates the first output only (`continueAfterHealthy = false`): the 5-second steady sampling is gone, a new output (surface/decoder change) still re-runs the startup validation. Trade-off: a decoder that turns green minutes into a healthy stream is no longer caught automatically on those devices; the frame/clock watchdogs remain.
- Buffers: ADAPTIVE starts at NORMAL (1.5 s to start / 2.5 s after a rebuffer) on every device instead of LOW; LOW itself is now 2 s / 8 s loading window, 1 s / 2 s start thresholds (was 1 s / 4 s, 0.5 s / 1 s). `prioritizeTimeOverSizeThresholds` deliberately stays `false`: with `true` Media3 keeps loading below the time floor regardless of the byte target, so a stream with broken timestamps could grow the sample buffer without bound on a 1-2 GB stick; the byte target (32/48 MiB) never binds for real streams below ~13-20 Mbit/s anyway, and `shouldStartPlayback` already starts on bytes.
- Watchdogs: buffer starvation 6 s -> 10 s, decoder frame stall 7 s -> 10 s, so Media3 can recover an ordinary provider hiccup on the open socket before the engine is rebuilt (one black screen per rebuild).
- Redirects: the live data source now follows an explicit http -> https upgrade once (shared `UpgradeOnlyHttpDataSource`, previously VOD-only); a downgrade to cleartext is still never followed because the stream path carries the line credentials. `setAllowCrossProtocolRedirects(true)` was not applied for that reason.
- Preview: `PlayerController(previewSurface = true)` / `setPreviewSurface()`; the Home thumbnail never samples (Exo and libVLC), the flag flips when the preview goes fullscreen.

Android 6.0 or newer (API 23). Production package: `com.iptv.player`; version code: `147`.
