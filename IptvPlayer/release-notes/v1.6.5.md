Details for maintainers (not published in the update prompt):

Fixes from the code audit of 23 Nov 2026 (findings list: 20 numbered items).

- Route learning on libVLC (`PlayerController.scheduleStallPoll`): `hasRecentOutputProgress()` was read twice per poll tick; the libVLC implementation moves its counter baseline on every call, so the second read was always false and `confirmLearning()` never ran on a VLC stage. Read once per tick.
- Stream fingerprint (`ExoPlayerEngine.resetHealth`): `frameRateEstimator` is reset between channels, so a channel without a frame rate in its format no longer reports the previous channel's fps.
- libVLC timeouts (`VlcPlayerEngine`): start, pause and resume timeouts stop the health poll and the one-shot output checks; they no longer call into a quarantined `MediaPlayer` or report a second failure.
- Late fatal error (`PlayerController.failPlayback`): the "process not replaced" callback only shows the error screen when no newer attempt started meanwhile.
- Early zap (`PlayerActivity.requestZap`): CH+/CH- before the controller exists is ignored instead of crashing on the uninitialised `lateinit`.
- Parental lock (`PinLockHelper`, `SettingsStore.getPin`, `PinAttemptPolicy`, `PinAttemptGuard`): adult detection also knows "Erotik", "Seks", "Yetişkin", "Erwachsene", "FSK 18", "Ab 18"; a stored PIN that cannot be decrypted reads as the default PIN instead of "no PIN" (lock stays on); the lockout deadline uses `elapsedRealtime`, so moving the clock no longer clears it (a reboot does; the failure count survives).
- Account change (`SourceRepository.activateSource` / `deactivateSource`, `LoginViewModel`, `ProfilesActivity`, `SettingsActivity`): stored stream URLs carry the login they were synced with, so a different account or a logout now clears the catalog tables (channels, guide, films, series, episodes and their search tables). Favorites, recents and channel overrides stay.
- Unreadable login (`SplashActivity.route`, `LoginActivity.EXTRA_RELOGIN`, `SourceConfig.isUsable`): a stored login that decrypts to blank goes to the login screen instead of syncing with blank credentials; nothing is deleted. `VodCatalogRepository.getVodDetail` no longer writes a blank stream URL back over the stored one.
- Films and series (`VodPlayerActivity`, `VodCompletionPolicy`, `PlaybackRouteMemory`): auto-next resumes an earlier bookmark of the next episode instead of overwriting it; an "ended" event with more than five minutes and more than a tenth of the running time left keeps the bookmark and is not marked watched; learned `VLC_HARDWARE` / `VLC_SOFTWARE` routes survive a restart. A real position is bookmarked even when the stream never reports a duration (`persistResume`). `VodPlayerActivity` is `singleTop`, so a second OK press no longer stacks a second player.
- Series dates (`SeriesCatalogRepository.refreshSeriesEpisodeDates`, `SeriesDao.markEpisodeDateChecked`): a series whose info cannot be used is stamped as checked, so the same broken ids no longer head every sweep.
- Favorites (`LibraryRepository.observeAllFavorites`): items of categories hidden in Content Manager are filtered like on the home rail.
- Announcements (`IptvApp.maybeShowAnnouncement`): the id is stored as shown only after the dialog was shown.
- Servers (`crash-receiver/server.js`, `crash-receiver/guard.js`, `support-desk/security.js`, `support-desk/server.js`, `support-desk/app.js`): the credential-redaction pattern is linear (80 KB of "a:" took 1.17 s before); ingest limits also have a per-address ceiling (50 devices' worth) because the device id is client-supplied; `pg` pools have an error listener; the Telegram call has a 10 s timeout; registrations and tickets have per-address day budgets. Both servers need a redeploy for this.
- Release workflow (`.github/workflows/android.yml`): the signed release now fails when `TELEMETRY_INGEST_KEY` is missing. v1.5.64 to v1.6.4 were built without it, so their telemetry and remote playback policy are off.

Not in this release: the panel's `is_adult` flag (the player API does not send it), archive path for the support-desk ticket cap.
