Automatik-Modus: Sender, die bisher nur mit einem manuell gewählten Player liefen, starten jetzt von selbst mit dem richtigen. Die App erkennt in Sekunden, ob ein Bild fehlt, ruckelt oder einfriert, wechselt sofort den Decoder und merkt sich das Ergebnis pro Sender und Sendertyp. Schnellere Senderwechsel, kein Decoderwechsel mehr bei reinen Netzproblemen.

Details for maintainers (not published in the update prompt):

- Bottleneck review (item 7.1): `MODE_SINGLE_PMT` is kept on purpose (Media3's progressive default; MULTI_PMT waits for every PAT-listed PMT and would never finish on filtered transponder relays, and could pair video/audio from different programs). The real "Exo loads forever, VLC plays" cause is a PMT-declared track that never carries data: Media3 never finishes preparing. New `LivePrepareStallPolicy` (8 s with >= 1 MiB received and no READY) hands such streams to the other hardware engine. `TsExtractor` gets `FLAG_IGNORE_SPLICE_INFO_STREAM` and `FLAG_ENABLE_HDMV_DTS_AUDIO_STREAMS` on top of the 1.6.1 flags; the timestamp search was already 1500 packets.
- VLC caching clamp (item 2): the 3000 ms cap stays. libVLC 3.x `AOUT_MAX_ADVANCE_TIME` is 3 s: audio timestamps further ahead than that fail conversion and every audio frame of the first seconds is dropped (observed in the field: "Timestamp conversion failed (delay 5000000 ... bound 3000000)"); a 4500/6000 ms cache would also add that much start latency on every VLC zap. VLC stalls are handled by rule A (network: same engine) and the bidirectional ladder (decoder: to Exo) instead.
- `VLC_SW` in AUTO (item 2b): withheld for >= 720p on every device (`SoftwareHdFallbackPolicy.automaticMode`), so AUTO runs between EXO and VLC_HW; SD (<= 576p) and light MPEG-1/2 keep the last-resort software rung. Kept exception: interlaced H.264 up to 1080 on an Amlogic box (hardware stalls, libVLC software with the deinterlacer off plays at full rate on a MiTV Stick); it is the only route left for those channels.
- Asynchronous zap (item 3): `ExoPlayerEngine.play(reset = true)` retires the old socket on the close executor and prepares the new item at once (no `awaitClosed(1500)`); `releaseAndThen` reports immediately so an engine swap no longer waits for the retired socket either. The server replaces the previous lease of the same device; the 10 s read timeout bounds the old socket. `stopAndThen` (Cast hand-off, another device) keeps its bounded wait.
- Rule A (network vs decoder): buffer starvation and clock stalls reconnect the same stage (unchanged); Media3 transport failures (`IO_NETWORK_CONNECTION_FAILED/TIMEOUT`, `IO_UNSPECIFIED` without an HTTP status) now report `networkCause` and never reach the engine ladder.
- Rule B (fast no-frame switch): no frame 4 s after READY (was 8 s), container parse errors (`PARSING_CONTAINER_*` -> `ExoPlaybackFailureClassifier.Failure.CONTAINER`) and decoder errors switch engines at once (`quickDecodeFailures` no longer waits for a second decoder error); VLC hardware "decoded but never displayed" bound 12 s -> 6 s (software keeps 12 s).
- Rule C (stutter switch): `FrameDropRatioGate` (> 25 % dropped over a 5 s window of the decoder counters, startup grace 3 s, cleared by rebuffers); `VIDEO_FRAME_STALL_HEALTHY_MS` = 3 s video freeze while audio advances and >= 1.5 s is buffered (10 s otherwise); `VideoHiccupDetector` + `HICCUPS_BEFORE_SWITCH` = 2 within 20 s of the first frame; VLC `VlcPlaybackHealth` freeze 7 s -> 3 s.
- Bidirectional ladder (item 5): AUTO from VLC_HW goes to EXO first, software last (`PlaybackRoutingPolicy`), for STARTUP/AUDIO/VIDEO/DECODE and the two-strike ERROR.
- Learning (item 6): `PlaybackLearnedRouting` (pure, tab-separated persistence) + `PlaybackLearnedRoutingStore` (SharedPreferences). Layer 1 channel -> stage after a decoder-class failure on A and 15 s uninterrupted playback on B (`LEARN_STABLE_MS`); layer 2 `StreamFingerprint` (`H264|1920|50i|eac3`: codec, resolution bucket, frame-rate family, interlace, audio) -> stage after two different channels, applied on the next start of any channel with a remembered fingerprint and pre-emptively when a new channel's fingerprint becomes known before its first frame; layer 3 device default after three different channels lost by the primary hardware engine to the other one, flipped back by the symmetric evidence; TTLs 14/30/30 days; a learned stage that fails again is dropped at once (`recordLearnedFailure`). Network/HTTP/start-timeout failures never feed it. Remote `startEngine` overrides still win. The old per-channel `PlaybackRouteMemory` stage memory is retired for live TV (its rebuffer record stays; VOD unchanged).
- Telemetry: `learned_route`, `learned_route_dropped`, `fingerprint_route`, `device_default`, `stutter_fallback` stability events (labels added to the crash receiver; deploy it to see them named in the panel).
- Tests: `StreamFingerprintTest`, `PlaybackLearnedRoutingTest`, `FrameDropRatioGateTest`, `LivePrepareStallPolicyTest`, `VideoHiccupDetectorTest`; updated `PlaybackRoutingPolicyTest`, `SoftwareHdFallbackPolicyTest`, `LiveVideoRouteTest`, `LiveTsExtractorPolicyTest`, `ExoPlaybackFailureClassifierTest`, `VlcPlaybackHealthTest`.
