Nach einer langen Pause startet die App beim Zurückkehren kurz neu, damit Sender wieder zuverlässig starten – ohne erneute Anmeldung.

Details for maintainers (not published in the update prompt):

- Field report on 1.5.98 (Fire TV class sticks): after 15-16 hours channels no longer opened and stayed on "Wird geladen…" until the stick was unplugged, while other players worked with the same account. 21 days of server logs showed no failed or rejected requests from those devices: the stuck state lived inside the long-running app process, and every screen keeps the screen on, so a stick left on an idle screen or the in-app screensaver never sleeps.
- `StaleProcessGuard`: when the app returns after at least four hours in the background or asleep, or the first key press arrives after four hours without input while no playback is running, the process restarts through the existing controlled playback process recovery (verified kill, clean-stop marker, relaunch). Players reopen their own screen, every other screen starts at the splash; logins and settings are untouched. Healthy playback is never interrupted, and nothing happens while a Cast receiver may own playback.
- Fix: the existing automatic playback process recovery (after a timed-out native libVLC stop in the background) was requested from the platform resume callback, where the AndroidX lifecycle is not yet RESUMED, so it never launched from there and the process could stay blocked on "Wird geladen…". Both checks now run right after the resume has completed.
- Launcher-equivalent relaunch intent, so after a recycle a later launcher press resumes the task instead of stacking a new splash.
- Before each recycle a compact state snapshot is sent as stability telemetry type `stale_process_recycle` (connection gate, playback owners, libVLC queue, QoE states, background sync) to identify the underlying stuck state.
- Diagnostics builds: `adb shell settings put global kululu_stale_recycle_ms 60000` shortens the threshold for device tests.

Android 6.0 or newer (API 23). Production package: `com.iptv.player`; version code: `143`.
