Details for maintainers (not published in the update prompt):

- Root cause of the "channels never open until the stick is unplugged" reports (customer log of 29 Sep 2026, Fire TV Stick 4K, 1.5.99): a libVLC hardware playback froze after 26 minutes, the software fallback could not release the old player (`native release timed out`), and the fail-closed connection gate asked for the controlled process recovery. That recovery has never worked in release builds: non-debuggable app processes are not dumpable and `/proc` is mounted with `hidepid=2`, so the `:playback_recovery` process cannot see `/proc/<pid>` of the main process, read it as "already gone", never killed it and relaunched the screen into the same poisoned process. Seven attempts in five minutes, one process id, "Wird geladen…" forever.
- Fix: the main process hands a Binder token to the recovery process (`EXTRA_MAIN_TOKEN`); `ProcessRecoveryVerifier` treats the token death reported by the kernel (plus `kill(pid, 0)`) as the evidence of liveness and death, and only falls back to `/proc` identity where it is readable. Verified on a non-debuggable build: the old process dies about 120 ms after the recovery starts and the screen reopens in a fresh process.
- 1.5.99 regression fixed: the four-hour stale-process guard used the same recovery, so on production devices it relaunched the splash inside the same process and then swallowed every remote key. The guard now gives the remote back when the process is still alive six seconds after the request, and the recovery reports `process_recovery_failed` to stability telemetry whenever it does not replace the process.
- Device tests of these paths must use a non-debuggable build (`assembleRelease` signed with any keystore, `LIVE_PLAYBACK_DIAGNOSTICS=1` for the switches); debug builds are dumpable and hide the bug.

Android 6.0 or newer (API 23). Production package: `com.iptv.player`; version code: `144`.
