Die Anmeldung funktioniert jetzt auch auf älteren Android-TV-Geräten (Android 6.0 und 7.0, z. B. Sony BRAVIA 2015), die bisher „NET-TLS – keine sichere Verbindung“ meldeten.

Details for maintainers (not published in the update prompt):

- Customer case of 5 Oct 2026: Sony BRAVIA 4K 2015, Android 7.0, date and time correct, every login failed with `NET-TLS`. The portal certificate (Let's Encrypt) chains to ISRG Root X1, which Android only ships since 7.1.1; the app talks HTTPS only and trusted system anchors only, so Android 6.0–7.1.0 devices could never log in. The account itself was fine (the household was watching through another app over http).
- Fix: ISRG Root X1 ships with the app (`res/raw/isrg_root_x1.pem`, fingerprint checked by a unit test). Android 7.0+ takes it from the network security config for every Java TLS stack (OkHttp, Media3, Coil); Android 6.0 has no network security config and gets the same anchor in code (`BundledRootTrust`: OkHttp clients and the `HttpsURLConnection` default); libVLC validates natively against the system store and receives the PEM through `--gnutls-dir-trust` on Android 6.0/7.0 only. The system store is always asked first; unknown roots are still rejected.
- Verification: new instrumented tests (`connectedDebugAndroidTest`, see docs/device-test-bench.md) run on Android 6.0, 7.0 and 14 emulator images against the chain kululu.live served on 5 Oct 2026: the app's effective trust accepts it, the stock system store alone rejects it on 6.0/7.0, libVLC reaches an HTTPS server only with the trust directory, and an OkHttp client still rejects a server with an unknown root. Not verified with a live handshake from an Android 7.0 device (the test PC's antivirus intercepts emulator TLS).
- Devices that cannot log in never see the in-app update prompt (it is shown on the dashboard): affected customers have to install this APK manually once.

Android 6.0 or newer (API 23). Production package: `com.iptv.player`; version code: `145`.
